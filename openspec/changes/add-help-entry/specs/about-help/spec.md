# Spec Delta

## Purpose

让用户能够从客户端关于页发现并打开现有使用说明，并在外部应用无法打开链接时获得明确反馈。该能力统一关于页帮助入口在移动端和桌面端的可见性、语言及操作预期，为后续实现和验收提供依据。

## ADDED Requirements

### Requirement: 关于页提供可识别的帮助入口

客户端 SHALL 在 Android、iOS、Windows、macOS 和 Linux 的关于页提供帮助入口，中文显示“使用帮助”，英文显示“Help”，并说明可查看客户端使用说明。

#### Scenario: 中文界面查看入口

- **WHEN** 用户在中文界面打开关于页
- **THEN** 页面显示“使用帮助”入口和中文用途说明
- **AND** 入口可通过关于页正常滚动到达并点击

#### Scenario: 英文界面查看入口

- **WHEN** 用户在英文界面打开关于页
- **THEN** 页面显示“Help”入口和英文用途说明

#### Scenario: 小窗口和大字体

- **WHEN** 用户在宽度 248 的逻辑像素窗口或字体缩放 1.8 倍的环境中查看关于页
- **THEN** 帮助入口可阅读、可滚动到达且可点击
- **AND** 页面不因新增入口出现布局溢出

### Requirement: 用户点击后打开既定的帮助文档

客户端 SHALL 仅在用户点击帮助入口时，请求外部应用打开 `https://github.com/sliencio/ting-reader-flutter/blob/main/README.md`，不得因为进入关于页而自动打开帮助文档。

#### Scenario: 点击帮助入口

- **WHEN** 用户点击帮助入口且系统接受外部打开请求
- **THEN** 客户端请求打开既定的本仓库 README 地址
- **AND** 客户端不把该操作解释为检查更新或下载安装包

#### Scenario: 只浏览关于页

- **WHEN** 用户打开关于页但没有点击帮助入口
- **THEN** 客户端不请求外部应用打开帮助文档

### Requirement: 链接打开失败时保留可用的关于页

客户端 SHALL 在系统拒绝打开链接或打开过程发生异常时向用户反馈失败，不产生未处理异常，并保留关于页的后续操作能力。

#### Scenario: 系统拒绝打开

- **WHEN** 用户点击帮助入口但系统返回无法打开链接
- **THEN** 客户端显示对应界面语言的失败反馈
- **AND** 用户仍能使用关于页和返回操作

#### Scenario: 外部打开过程抛出异常

- **WHEN** 用户点击帮助入口且外部打开过程抛出异常
- **THEN** 客户端通过既有错误反馈方式展示原因
- **AND** 不产生未处理异常

### Requirement: 既有关于页功能保持可用

客户端 SHALL 在新增帮助入口后保留客户端与服务端版本展示、既有更新操作、项目仓库、更新日志、问题反馈、开源许可和致谢入口的原有行为。

#### Scenario: 继续使用既有入口

- **WHEN** 用户在新增帮助入口后的关于页查看版本或使用既有链接
- **THEN** 版本信息仍可正常展示
- **AND** 既有链接仍请求打开原有目的地
- **AND** 新增帮助入口不会触发额外的更新请求
